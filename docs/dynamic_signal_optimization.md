# Dynamic Traffic Signal Optimization Engine

## Overview
The **Dynamic Traffic Signal Optimization Engine** (`DynamicSignalOptimizer`) is a pure CV/business-logic simulation module that calculates safe, explainable, and bounded traffic signal timing recommendations based on real-time traffic state metrics.

> [!NOTE]
> **Simulation Disclaimer**: This engine produces recommended signal timing values for visual tracking HUDs, simulation, and analytical modeling. It does **NOT** control physical traffic signal hardware, relays, ESP32 microcontrollers, or real-world intersection controllers.

---

## Inputs & Dependencies
The optimizer consumes the structured output dictionary generated by `TrafficDensityEngine` (`cv/detection/density.py`):

```json
{
    "active_vehicle_count": 7,
    "smoothed_vehicle_count": 6.5,
    "density_level": "MEDIUM",
    "congestion_level": "MODERATE",
    "class_counts": {
        "car": 5,
        "motorcycle": 1,
        "bus": 0,
        "truck": 1
    }
}
```

---

## Signal Timing Formula & Bounding

### 1. Recommended Green Time Calculation
Green time is calculated using the project's established linear allocation formula:

$$\text{raw\_green} = \text{base\_green} + (\text{smoothed\_vehicle\_count} \times \text{time\_per\_vehicle})$$

- **Default Base Green** (`base_green`): $20\text{ seconds}$
- **Default Vehicle Multiplier** (`time_per_vehicle`): $3.0\text{ seconds per vehicle}$

### 2. Safety Bounds Enforcement
To guarantee safety and prevent invalid or excessive signal durations, green time is strictly bounded:

$$\text{recommended\_green\_time} = \max(\text{min\_green}, \min(\text{max\_green}, \text{int}(\text{round}(\text{raw\_green}))))$$

- **Minimum Green Bound** (`min_green`): $20\text{ seconds}$
- **Maximum Green Bound** (`max_green`): $60\text{ seconds}$

### 3. Yellow & Red Signal Allocations
- **Yellow Duration** (`yellow_time`): Fixed at $5\text{ seconds}$.
- **Red Clearance Duration** (`red_time`): $\max(\text{min\_red}, \text{recommended\_green\_time} - \text{yellow\_time})$. Default $\text{min\_red} = 20\text{s}$.

---

## Why Temporal Moving-Average Smoothing is Used
A raw computer vision tracking pipeline produces frame-by-frame fluctuations in visible vehicle counts (e.g. temporary occlusion, vehicles passing behind large trucks, or confidence threshold variations). 

If raw per-frame counts were fed directly into signal calculations, recommended green times would flicker wildly every fraction of a second. By using `smoothed_vehicle_count` (a rolling 5-frame moving average from Step 3), the signal recommendation stabilizes, reflecting genuine traffic trend changes rather than per-frame noise.
